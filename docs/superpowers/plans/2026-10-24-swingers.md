# Swingers — piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** riscrivere Swingers come plugin MIDI (VST3, AU MIDI FX, CLAP) più standalone che converte le note di batteria tra drum map passando per il GM, con eccezioni per coppia, editor delle mappe e conversione di file senza perdita di timing.

**Architecture:** un motore in C++ senza grafica (`core/`, solo `juce_core` e `juce_audio_basics`) che costruisce una tabella di 128 voci e la applica a messaggi MIDI dal vivo o a un `juce::MidiFile` letto a tick. Sopra, un `AudioProcessor` JUCE che è effetto MIDI, e un'interfaccia JUCE (pannello compatto, patchbay, editor delle mappe, barra file solo nello standalone).

**Tech Stack:** C++20, CMake ≥ 3.22, JUCE 8.0.4 (AGPL-3.0), clap-juce-extensions, Catch2 v3.5.2.

**Spec:** `docs/superpowers/specs/2026-10-24-swingers-design.md`

## Review Focus

- **XML di Cubase con `<`, `>`, `&` non escapati nei nomi** (`[Ride ><] *Ride Tip`): l'import deve riuscire e conservare il nome. Test nel Task 3.
- **Note-on con velocity 0** usati come note-off (molti file e controller lo fanno): devono comportarsi da note-off, senza note appese. Test nel Task 5.
- **Due note d'origine sulla stessa nota d'arrivo, sovrapposte**, o cambio di mappa con note tenute: nessuna nota deve restare appesa e ogni note-off deve uscire. Test nel Task 5.
- **File MIDI formato 0** (tutti i canali in una traccia) e formato 1, con risoluzione diversa da 480: formato, risoluzione e tick devono restare identici. Test nel Task 6.
- **Id di mappa in conflitto**: una mappa utente con lo stesso id della GM inclusa, o due import con lo stesso nome; l'inclusa non si sovrascrive mai e il secondo import prende `-2`. Test nel Task 7.

### Task 4: Eccezioni di coppia e tabella di conversione

**Files:**

**Interfaces:**
- Consumes: `DrumMap`, `kNoGm` (Task 2).
- Produces:
  ```cpp
  struct PairOverrides {
      juce::String fromId, toId;
      std::map<int, int> direct;      // source note -> target note
      std::set<int> dropped;          // source notes discarded on purpose
      bool empty() const;
      void connect (int source, int target);   // removes `source` from dropped
      void drop (int source);                  // removes `source` from direct
      void reset (int source);                 // removes it from both
  };
  juce::var toJson (const PairOverrides&);
  std::optional<PairOverrides> pairOverridesFromJson (const juce::var&, juce::StringArray& problems);
  // file: {"format":"swingers-pair","version":1,"from":…,"to":…,"direct":[{"note":60,"to":33}],"dropped":[61]}

  enum class Route : uint8_t { Standard, Override, DroppedByUser, NoMatch };
  struct RouteEntry { int target = -1; Route route = Route::NoMatch; int gm = kNoGm; };
  struct ConversionTable {
      std::array<RouteEntry, 128> entries {};
      static ConversionTable build (const DrumMap& from, const DrumMap& to, const PairOverrides* overrides);
      static ConversionTable identity();       // every note to itself, Route::Standard
  };
  ```

### Task 5: Instradamento delle note e remapper dal vivo

**Interfaces:**
- Consumes: `ConversionTable`, `Route` (Task 4).
- Produces:
  ```cpp
  class NoteRouter {   // shared by the plugin and the file converter
  public:
      enum class Outcome { Pass, Remapped, Dropped };
      Outcome route (juce::MidiMessage& m, const ConversionTable& t, int channel);   // channel 0 = all, 1..16
      void reset();
  private:
      std::array<int16_t, 16 * 128> held_;   // -1 none, -2 dropped, else target note
  };
  class LiveRemapper {
  public:
      void setTable (const ConversionTable&);   // message thread
      void setChannel (int channel);            // 0 = all
      void process (juce::MidiBuffer&);         // audio thread, no allocation
      uint32_t activity() const;                // routed note-ons so far
      uint32_t hits (int sourceNote) const;     // routed note-ons for that source note
  };
  ```
- Comportamento di `route`: messaggi non di nota, o su un canale escluso → `Pass` intatti. Note-on con velocity > 0: secondo la tabella, ricorda in `held_` dove è andata → `Remapped` o `Dropped`. Note-off (anche note-on con velocity 0): usa `held_` se c'è (anche se nel frattempo la tabella è cambiata) e lo libera, altrimenti la tabella. Aftertouch polifonico: `held_` se c'è, altrimenti la tabella.
- `LiveRemapper`: tabella in attesa protetta da `juce::SpinLock`; in `process` un `ScopedTryLockType` copia la tabella nuova nella attiva solo se il lock si prende, altrimenti usa l'ultima. `process` riscrive il buffer togliendo i messaggi `Dropped`; il buffer d'appoggio è preallocato in `setTable`/costruttore (`ensureSize(2048)`).
